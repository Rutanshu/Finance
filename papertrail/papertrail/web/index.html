How to use PaperTrail

The whole tool exists to answer one question quickly: this number is wrong — where did it come from?

Step 1 — Scan

Type the path of the folder your month-end workbooks live in and hit Scan folder. PaperTrail opens each workbook read-only and pulls out every cross-file formula reference — things like ='[Revenue_Register.xlsx]Data'!$B$4 — plus the external-link table hidden inside the file. Each of those becomes an arrow on the map. Click any arrow and it opens down to the exact tab, column and formula behind that handoff — not just "file A feeds file B."

Step 2 — Declare the invisible handoffs

Here is the honest limitation of every scanner ever written: a copy-paste leaves no trace in the file. Neither does an email, nor someone re-keying figures off a PDF. Those are usually your highest-risk hops, and only a human can tell you they exist.

So: click + Declare a handoff, pick the source and destination workbook, and say how the data actually moves — pasted, emailed, or typed. It is saved to papertrail.annotations.json in your own folder. Ten minutes with whoever runs the close is enough to capture them all.

Step 3 — Trace

Turn on Trace and click a workbook. Everything unrelated fades out and you are left with the exact chain: every file upstream that feeds it, and every file downstream that depends on it. Two directions, two uses:

  • Upstream — "Revenue looks off." Follow it back to the source. Usually you land on a dashed line.
  • Downstream — "The bank changed its CSV format." Instantly see which reports are now unsafe, before anyone presents them.

Click any single arrow (or the "N columns traced" chip in a workbook's Fed by / Feeds list) to open the tab-and-column breakdown for just that one handoff: which sheet and column on the source side, which sheet, column and header it lands on, how many cells, and a sample of the actual formula text.

Or drill in from the workbook itself: select it, then click a sheet name under Sheets. The other sheets step out of the way and that one sheet opens into exactly which columns it receives, from where, and which columns it sends out to other files — end to end, one sheet at a time. Click "‹ back" to return to the list.

When a map gets busy, select a workbook and turn on Isolate — everything outside its up/downstream chain is hidden, not just dimmed. If several sources merge into that one file, a Flow stepper appears so you can step through each upstream route one at a time instead of looking at all of them tangled together.

Workbooks with a dashed pill-shaped box feeding them (🌐 🗄️ ☁️ 📧 📁 🔗 📡) are pulling data from outside the scanned folder entirely — a database connection, a Power Query web/SharePoint/Exchange source, a legacy web query, or a formula like WEBSERVICE() that reaches the internet on every recalculation. Click one of those pills for detail; credentials in database connection strings are redacted before they're ever shown.

Step 4 — Work the findings

The Findings tab is ordered worst-first. It flags fragile handoffs, broken links to files that are not in your folder, volatile formulas that no tool can trace through (INDIRECT, OFFSET), hardcoded constants buried in formulas, and orphan workbooks that nothing appears to feed.

Step 5 — Re-run it monthly

Rescan after each close. Your annotations persist, so you only ever describe a handoff once. Export the Handoffs tab to CSV and it doubles as audit evidence that someone has actually looked at the pipeline.

The one fix worth doing first

At every fragile handoff, carry one number that must match on both sides — a row count, a gross total, or a hash of the key column. Put it in a visible cell with conditional formatting that turns red on mismatch. Most spreadsheet finance errors surface within seconds once that exists. PaperTrail tells you where to put them.

Running it

pip install -r requirements.txt
python -m papertrail                        # then paste the folder path in the UI
python -m papertrail "C:\Finance\Month-end" # or scan on startup
python -m papertrail --port 9000 --no-browser

Limits — worth being clear about

  • For cross-file formulas it resolves the exact source tab, column and cell — but it does not recompute the number for you. It tells you where to look, not what the number should be.
  • Lineage within one workbook (sheet A feeds sheet B in the same file) is still summarised at the sheet level, not drawn cell-by-cell. If you need that, pycel is the tool for it.
  • INDIRECT and OFFSET build references at runtime, so no static tool can follow them. They are flagged, not traced.
  • A reference to a named range or a whole column (A:A) is still shown as a file-level handoff — the column view only fills in when the formula points at a specific cell or range.
  • Files outside the scanned folder show up as broken links — which is itself useful. Shadow workbooks on someone's desktop are exactly what you want to discover.
  • Password-protected or corrupt files are reported as unreadable rather than skipped silently.

Why this matters

Excel is not the problem. Undocumented handoffs between spreadsheets are the problem.

A formula error is visible and usually caught. What is not visible is that the revenue block in the trial balance is pasted in by one person every month, from a file that is itself pasted together from two exports whose date filters are chosen by hand. Nothing in the workbook records that. It lives in one person's memory — and it walks out of the door when they do.

What you get

1. Close the month faster

Most "the numbers don't tie" hours are spent working out where a figure came from, not fixing it. Tracing back is a click instead of an afternoon of asking around.

2. Survive an audit without heroics

Auditors ask for the flow of financial information end to end. Most companies redraw it by hand each year from memory. Export the Handoffs tab and it is done — and it is accurate, because it was read out of the files.

3. Reduce key-person risk

When the person who runs the close leaves, the map stays. Onboarding their replacement becomes a walkthrough rather than an archaeology project.

4. Make the risk arguable

"Our process is a bit manual" gets no budget. "Sixty percent of our reporting pipeline moves by copy-paste, here are the eleven specific hops, ranked" gets a decision. The tool turns a feeling into a list.

5. Aim automation where it pays

If you ever move to a proper system, the fragile handoffs are the migration order. You automate the eleven hops that matter instead of rebuilding everything.

Why it runs locally — and how you can verify that

Finance data is the most sensitive data a company holds. So this is not a cloud service with a privacy policy, it is a program on your machine with no way to phone home:

  • The server binds to 127.0.0.1 only. Not 0.0.0.0. Nothing else on your network can reach it.
  • No HTTP client is imported anywhere in the package. Check it yourself: grep -rn "requests\|urllib.request\|httpx\|socket.connect" papertrail/ returns nothing.
  • No CDN, no web fonts, no analytics. The page is one HTML file served from disk, with a connect-src 'self' content-security policy on top.
  • Workbooks are opened read-only. The only file written is papertrail.annotations.json, in your own folder.
  • Want certainty? Pull the network cable and run it. Everything works.

Where it sits next to existing tools

Cell-level tools (pycel, ExceLint) map A1 feeds B7 inside a workbook. Enterprise lineage platforms (OpenLineage, Marquez) map database pipelines and assume instrumented jobs. Neither can see a human carrying a file between two workbooks — which in a spreadsheet-run finance function is most of the pipeline. That gap is what PaperTrail fills.
